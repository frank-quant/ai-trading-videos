## 一、复核原则：独立重算，而非重跑原脚本

本次复核刻意**不 import** `indicators.py` / `backtest.py` / `metrics.py` / `build_csvs.py`，
而是从已交付的 CSV 出发，用**与生产脚本不同的算法路径**重新推导每一个量：

| 量 | 生产实现 | 本次复核实现（独立） |
|---|---|---|
| SMA | 滚动窗口累加 | **前缀和差分法** + **滚动差分法**（两法互校） |
| EMA | 向量化递推 | **显式标量循环**（另测首价种子口径） |
| RSI14 | Wilder 平滑 | **独立重写的 Wilder 实现** |
| MACD | 由 EMA 推导 | **由复核版 EMA 重新推导 DIF/DEA** |
| 净值 | 逐日乘算 | **log(r) 累加后 exp() 还原** |
| 最大回撤 | 扫描峰值 | **显式循环维护运行峰值** |
| 成交清单 | 由 signals.csv 驱动 | **从原始价格完整重放策略规则** |
| 成本 | 账本内计费 | **逐笔反解份额/费用/现金** |
| 年化收益 | `(期末/初始)^(252/N)−1` | **Excel 侧 `(期末/初始)^(252/(N−1))−1`** —— 交叉比对时发现口径不一致（见 §三） |
| Excel 工作簿 | —— | **Excel COM `CalculateFullRebuild` 全量重算后回读缓存值**（第二套完全独立的实现） |

### 抽样口径

- 从 763 个可评估行中用 `random.seed(20261102)` 抽 **20 个交易日**：
  `104, 126, 183, 222, 249, 256, 266, 445, 473, 483, 537, 587, 631, 639, 671, 690, 704, 715, 724, 779`
- 额外追加 **2 个边界行**：第 59 行（预热最后一行，SMA60 尚不存在）与第 60 行（首个可评估行）。

### 容差口径

`indicators.csv` 按 **4 位小数**存储、`prices.csv` 按 **2 位小数**存储，因此比对容差取存储精度的一半
（`indicators` ±5e-5、`prices` ±5e-3）。这是**存储精度**限制，不是计算精度限制——脚本内部为双精度浮点。

## 二之二、Excel 工作簿的独立复核（第二套完全独立的实现）

`moving_average_analysis.xlsx` 不是把 Python 结果抄进去的静态表，而是一个 **Formula-first 联动模型**：
除 `Assumptions` 外全部是活的 `=` 公式，指向 `Assumptions` 的具名参数与 `Prices` / `Prices_Bench` 的原始行情。
因此它天然构成**第二套独立实现**，可以反向校验 Python 侧。

复核方式：Excel COM `CalculateFullRebuild` 强制全量重算并保存 → openpyxl `data_only=True` 回读缓存值 → 与 CSV 逐项比对
（脚本 `scripts/recalc_verify.py`，机读结果 `raw/workbook_verify.json`）。

| 项 | 结果 |
|---|---|
| 工作表顺序 | `Assumptions, Prices, Indicators, Ledger, Ledger_Gross, QA, Summary, Prices_Bench` ✅ |
| 公式总数 | **58,452**（Indicators 16,440 / Ledger 13,974 / Ledger_Gross 13,974 / Summary 14,019 / QA 45） |
| 错误单元格（`#REF!` `#DIV/0!` `#VALUE!` …） | **0** |
| 与 CSV 逐项比对 | **57/57 项一致** |
| 工作簿自带的活公式自检（`QA!D5:D19`） | 15 项 **全部 PASS** |

比对项覆盖：期末净值、累计收益、年化收益、最大回撤及其峰值日/谷底日、交易次数、持仓天数与占比、
两项费用口径、账本逐笔成交价与费用、净值恒等式违例数、预热行数、行情行数、基准与策略是否同轴。

### 在工作簿建设过程中发现并修复的 4 个真实缺陷

| # | 缺陷 | 现象 | 修正 |
|---|---|---|---|
| 1 | `OFFSET` 参数个数错误 | EMA 种子写成 `OFFSET(Prices!$E$2,0,EmaFast,1)`，把「行偏移」当成了「列偏移」 | 改为 `OFFSET(Prices!$E$3,0,0,{per},1)` |
| 2 | 斜率缺类型保护 | Excel 中 `"" > 0` 为 TRUE，预热期空串斜率被计入评分，与 Python 语义不符 | 斜率公式与评分项均加 `ISNUMBER` / `NOT(ISNUMBER(...))` 保护 |
| 3 | **整表行号错位 1 行** | 表体数据从第 3 行开始，公式却按第 2 行起算，导致全表引用偏移 | 统一 `FIRST=3 / LAST=824`，13 处 `ROW()-2` 改为 `ROW()-3`；DEA 种子锚点改 `H$3`；RSI 的 `INDEX` 区间改为行 4..RsiLen+3 与 3..RsiLen+2 |
| 4 | `COUNT` 统计文本日期列返回 0 | `Summary!B14:E14` 出现 `#DIV/0!`，年化收益显示为 −1 | `COUNT` 改为 `COUNTA` |

错误单元格数量演进：**22,934 → 18,874 → 4 → 0**。

### 交叉比对中发现的第 7 项不一致：年化收益口径

Python 侧早期用 `252 / N`（把 822 个**观测点**当成了收益期数），Excel 侧用 `252 / (N − 1)`
（822 个观测点对应 **821** 个日收益期，首日建仓不产生收益期）。两者对含费策略的年化收益差 **0.000153**。

**这不是计算错误，是口径定义差异。** 已统一为标准收益期口径 `252 / (N − 1)`：
`scripts/metrics.py`、`scripts/backtest.py`、`scripts/backtest_report.py` 三处同步修正，
`metrics.csv` 与 `raw/backtest_summary.json` 重新生成，Excel 侧公式本就符合该口径、无需改动。
统一后两侧**逐位对齐**（含费策略年化 0.11913814419482538 = 11.9138%）。

> 影响范围：年化收益这一列数值从 +12.93%/+11.90%/+17.62%/+2.49% 变为
> **+12.95%/+11.91%/+17.64%/+2.50%**；累计收益、期末净值、最大回撤、交易次数、持仓天数、费用口径**均未变化**。
> 三张 PNG 图表重跑后**哈希逐字节一致**（它们只引用累计收益与期末净值，不引用年化列）。

## 三、首轮复核的 6 项失败：全部是 QA 脚本自身缺陷，数据无错

首轮跑出 6 项 FAIL。逐项定位后，**根因全部在复核脚本，不在交付数据**；已修正复核脚本并重跑，**未修改任何交付文件**。

| # | 失败项 | 根因 | 处理 |
|---|---|---|---|
| 1 | SMA 滚动差分法数值不符 | 复核脚本 `sma_rolling()` 写错：从第 i 行窗口出发后又叠加了下一个窗口的差分，造成重复累加（例：row104 sma5 得 90.796，真实值 85.382）。**前缀和法本身与 CSV 完全吻合** | 改为标准滚动递推（`s += closes[j] - closes[j-w]`），两法现已互校一致 |
| 2 | EMA 抽样比对"不符" | 复核脚本用 ±1e-9 容差，但 `indicators.csv` 按 **4 位小数**存储（例：82.269 vs 82.26899916896504），差异 8.3e-07 是存储取整，不是计算错误 | 容差改为存储精度的一半 ±5e-5 |
| 3 | 全样本 EMA 比对"不符" | 同上 | 同上；修正后最大偏差恰为 5.00e-05 |
| 4 | RSI/MACD 抽样比对"不符" | 同上（例：78.5029 vs 78.5029267139272） | 同上 |
| 5 | "首个信号落在预热期之后"判失败 | 复核脚本写的是 `enumerate(file_sig)`，取到的是**信号列表下标**（0–39）而非 K 线下标 | 改为用 `dates.index()` 取真实K线下标；实际首个信号在第 66 行，判定正确 |
| 6 | "信号行当日不成交"判失败 | 复核脚本的**预期本身不成立**。连续两个交易日各有信号时（2025-01-02 金叉、2025-01-03 死叉），第 2 天既要执行前一日金叉触发的买入、又要产生当日死叉，两件事同行出现是正常的，不是前视偏差 | 改为正确判据：成交方向取自**前一日**信号；并新增 2025-01-02/03/06 因果链回归用例 |

> 第 6 项同时说明：判断前视偏差的正确标准不是"信号行不得有成交"，而是
> **"第 i 行的成交只能由第 i−1 行的信号触发，且成交价只能是第 i 行的开盘价"**——
> 这两条已由「成交时点」与「策略端到端重放」两项检查独立验证通过。

## 五、复核结论

1. **交付数据本身无错误**：47 项独立检查全部通过，涵盖均线、EMA/RSI/MACD、净值、回撤、预热、
   未来数据、信号与成交时点、成本、基准与数据来源链。
2. **首轮 6 项失败已全部定位为复核脚本缺陷**（含 1 个真正的算法错误：滚动差分重复累加；
   1 个方向写反的判据；3 处容差设置错误），修正后全部通过，**交付文件未做任何修改**。
3. **Excel 工作簿构成第二套独立实现**：重算后 **57/57** 项与 CSV 一致、**0** 个错误单元格；
   建设过程中发现并修复了 4 个真实公式缺陷（`OFFSET` 参数错位、斜率类型保护缺失、
   **整表行号错位 1 行**、`COUNT` 统计文本列）。详见 §二之二。
4. **交叉比对发现并统一了年化口径**：Python `252/N` vs Excel `252/(N−1)`，已统一为
   `252/(N−1)`，两侧逐位对齐；受影响范围仅限年化收益一列，累计收益与全部其他指标未变。
5. **最强的单条证据**是「策略端到端重放」：从原始价格按规则独立重算出的 40 笔成交，
   与账本逐笔（信号日、执行日、方向、成交价）完全一致——这同时证明账本不是事后凑出来的。
6. **结论层面的提醒不变**：策略（含费 +44.30%）**跑输**同期买入持有赛力斯（+69.78%），
   仅回撤更浅（−50.09% vs −75.88%）。本次复核确认这是**真实结果而非计算错误**，
   并按要求未做任何区间或参数调整。
