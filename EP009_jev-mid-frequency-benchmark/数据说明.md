- 市场：币安 USDⓈ-M BTCUSDT 永续合约，每 300 毫秒一个决策点，共 279,257 个
- 只读公开行情、只做模拟，没有下过任何订单

## 怎么用

1. 拿到测试台代码（零依赖，需要 Node.js 22 或更高）：

   ```bash
   git clone https://github.com/frank-quant/ai-trading-videos.git
   cd ai-trading-videos/EP009_jev-mid-frequency-benchmark/jev-hft-bench
   ```

2. 解压压缩包，把 `20260925_1004` 整个文件夹放到 `jev-hft-bench/data/` 下面（`data` 文件夹没有就自己建一个）。放好后应该是：

   ```
   jev-hft-bench/data/20260925_1004/decisions.jsonl
   ```

3. 启动服务，浏览器打开 http://localhost:8770 ：

   ```bash
   node server.mjs
   ```

4. 「历史」页选这一场：可以按 1–300 倍速回放、从第 N 小时开始、重新分析。不需要任何 key。

重新分析 28 万行数据比较吃内存，建议 16 GB 以上。命令行重跑：

```bash
node --max-old-space-size=12288 analyze.mjs data/20260925_1004
```

## 文件清单

| 文件 | 大小 | 内容 |
|---|---|---|
| `decisions.jsonl` | 222 MB | 快档：每个决策点一行。各选手给出的上涨概率（`p`）、3 / 10 / 30 / 60 秒后的实际涨跌（`out`）、Jev 的回答时刻与回答后的涨跌（`m` / `after`）、每个选手的模拟挂单（`mk`） |
| `features.jsonl` | 94 MB | 每个决策点喂给模型和规则的行情特征：买一卖一、价差、盘口失衡、订单流、近期涨跌、近 30 秒成交统计 |
| `mids.csv` | 8 MB | 买一 / 卖一价格序列（`t,bid,ask`），约 300 毫秒一行 |
| `slow.jsonl` | 0.4 MB | 慢档：每 60 秒问一次 Jev 和 DeepSeek，判断 5 / 15 分钟后的涨跌 |
| `meta.json` | | 这一场的配置（档位、周期、手续费假设、中断区间） |
| `run.log` | | 运行日志（行情断线重连、中断续跑都在里面） |
| `results.md` / `.json` | | 自动分析出的结果表（和仓库 [`results/`](results/) 里的一样） |
