# EP009 · Jev 做中高频交易靠不靠谱

📺 看视频：B站 · YouTube（发布后补链接）

[Jev](https://typesafe.ai) 是 TypeSafe 发布的决策模型（官方叫 System One 模型）：不写文字，只做选择题，直接给出选项和概率，官方称一次 70–500 毫秒。
发布第二天，Monad 的工程师开源了 [jev-trader](https://github.com/jarrodwatts/jev-trader)，每 0.3 秒问一次 Jev「接下来 30 秒涨还是跌」，然后自动挂单。

这一期我基于 jev-trader 修掉两个问题，做了一个**币安 BTC 永续合约的测试台**，让 Jev 跟 **8 条中高频对照策略、DeepSeek、一枚硬币**同场比了 **24 小时**（279,257 个决策点）。

**结论：Jev 确实能判断涨跌，但不如最好的经典策略准；在秒级这个尺度上，这点判断力变不成钱。**

本目录放的是可复现的全部材料：测试台代码、正式场结果和补算脚本。**只读公开行情、只做模拟，不下任何订单。**

## 结果速览

正式场：2026-09-25 10:04 → 09-26 10:04（北京时间），Binance USDⓈ-M BTCUSDT 永续，每 300 毫秒一个决策点。

| 选手 | 3 秒准确率 | 30 秒准确率 | 挂单 30 秒估值 乐观 / 保守（bps） | 零手续费理论收益（bps） |
|---|---|---|---|---|
| QI 盘口失衡 | **71.9%** | **57.9%** | +0.27 / −0.56 | 11,324 |
| DI 深度失衡 | 70.8% | 57.6% | +0.30 / −0.44 | 10,941 |
| BASE jev-trader 基准规则 | 66.3% | 55.3% | +0.23 / −0.56 | 8,881 |
| **Jev** | **65.4%** | **54.7%** | **+0.14 / −0.83** | **3,391** |
| OFI 订单流不平衡 | 64.9% | 54.4% | +0.14 / −0.79 | 6,917 |
| MOM 短期动量 | 57.3% | 51.7% | +0.02 / −0.87 | 4,211 |
| TFI 成交失衡 | 54.8% | 52.1% | +0.03 / −0.79 | 1,537 |
| RAND 抛硬币 | 50.0% | 50.1% | −0.12 / −1.05 | −26 |
| VWAP 回归 | 42.4% | 47.0% | −0.24 / −1.07 | −2,422 |
| REV 短期反转 | 41.0% | 47.3% | −0.25 / −1.09 | −3,422 |

> Jev 的准确率从它**回答完那一刻**起算（能拿来交易的口径）；规则在决策时刻就有答案。
> 理论收益 = 每个选手按自己的判断持有 1 个单位、按中间价计价、不算手续费，**现实中做不到**，只用来比较判断质量。算上吃单手续费后，10 条曲线全部为负。

### 四个问题

**1. Jev 能不能判断涨跌？能。** 30 秒准确率 54.7%，95% 置信区间 53.6% ~ 55.8%（按 60 秒分块自助法），比抛硬币高 4.6 个百分点。

**2. 跟经典策略比？赢 4 条、平 2 条、输 2 条。** 输给 QI 和 DI：30 秒上比 QI 低 3.3 个百分点（2.3 ~ 4.2），Bonferroni 校正后仍显著。
这不是因为慢：把 Jev 按提问那一刻算，30 秒 55.1%，还是差近 3 个点。
事后补算还发现：Jev 和 jev-trader 自带的三行基准规则 87% 的时候判断一样；用前 12 小时把 QI 和 Jev 组合起来训练、后 12 小时检验，QI 单独 70.9%，加上 Jev 70.8%，**没有提升**；逐小时比，3 秒准确率上 Jev **没有一个小时**赢过 QI。

**3. 能不能变成钱？不能。** 这 24 小时 BTC 30 秒平均只波动 2.2 bps，而普通用户（VIP0）一买一卖的手续费，挂单 4 bps、吃单 10 bps。
挂单按保守口径（价格打穿才算成交）全员为负，连 QI 也是：被成交的单，往往正是判断错的时候（逆向选择）。

**4. 跟大模型比？** 慢档每 60 秒问一次、判断 5 / 15 分钟后的涨跌：DeepSeek-V4-Pro 一次约 76 秒，Jev 1.5 秒；5 分钟准确率 50.6% / 50.8%，抛硬币 50.7%，三者分不出来（能独立算的窗口只有两百多个）。
24 小时花费：Jev 13.8 万次调用 $15.86，DeepSeek 1,410 次 ¥159.5（按两家账单）。

## 自己跑一遍

需要 **Node.js 22 或更高**，没有任何 npm 依赖。

```bash
git clone https://github.com/frank-quant/ai-trading-videos.git
cd ai-trading-videos/EP009_jev-mid-frequency-benchmark/jev-hft-bench
node server.mjs
```

浏览器打开 http://localhost:8770 ：在「设置」页填 Jev / DeepSeek 的 key，「运行」页点开始；没有 key 可以点「试运行」，只跑 8 条策略和抛硬币。
key 只存在你本机的用户目录里，不进仓库。详细说明、每条对照策略的公式和论文出处，见 [`jev-hft-bench/README.md`](jev-hft-bench/README.md) 和网页里的「方法」页。

### 只想看我跑的那一场

正式场的原始数据约 320 MB（每个决策点一行，共 28 万行），太大没放进仓库，**获取方式见视频简介**。
下载解压后把 `20260925_1004/` 放到 `jev-hft-bench/data/` 下，启动服务，在「历史」页就能按任意倍速回放、重新分析。

事后补算（一致率、增量价值、逐小时对打、延迟拆解、概率质量、手续费墙）可以用 `scripts/` 里的两个脚本重跑：

```bash
node --max-old-space-size=12288 scripts/final_extra.mjs        jev-hft-bench/data/20260925_1004
node --max-old-space-size=12288 scripts/final_extra_hourly.mjs jev-hft-bench/data/20260925_1004
```

## 几点说明

- **只测了一个市场、一天。** 结论只代表币安 BTC 这 24 小时，换市场、换时间段不一定一样。
- **对 jev-trader 做了三处修改**：提示词如实描述挂单（原版说的是市价单）、每次请求加 5 秒超时、只记录判断不模拟仓位。市场从 Monad 上的 MON-USDC 换成了币安 BTC：MON 价差有十几个 bps，挂单能吃到价差；BTC 只有约 0.01 bps，所以这里的挂单结果只作参考。
- **修正记录**：9/25 之前的两场试跑，喂给 Jev 的挂单深度字段有问题（沿用了原版「距中间价 10 / 25 / 50 bps」的口径，在 BTC 上三组数相同且失真），修正后重跑。本目录的结果全部来自修正后的正式场。
- **服务中断过一次**：9/25 15:34 – 15:40 中断 5.9 分钟，自动续跑，中断时段不计入任何统计。
- **事后补算要当探索性分析看**：它们是看到结果之后才做的，没有预先登记。
- 从中国大陆调用 Jev，延迟中位数 360 毫秒（P90 400、P99 541），一半的决策点因为上一题还没答完被跳过（与 jev-trader 原版的处理一致）。
