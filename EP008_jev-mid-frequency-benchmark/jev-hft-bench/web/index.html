测试目的Purpose

检验 Jev（TypeSafe System One 模型）在中高频尺度上做方向判断是否有效：在同一份币安 BTCUSDT 永续行情、同一套结算规则下，与八类经典的无参数中高频信号及随机基准比较方向准确率、挂单成交质量和累计收益；另在分钟级尺度与通用大模型比较。

中高频指亚秒级决策、秒级到分钟级预测。真正的高频交易是微秒级、服务器托管在交易所机房，不在本测试范围内。

Does Jev (TypeSafe's System One model) make useful directional calls at mid-frequency horizons? On the same Binance BTCUSDT perpetual feed and the same settlement rules, Jev is compared with eight classic parameter-free microstructure signals and a random baseline on hit rate, maker fill quality and cumulative P&L; at minute horizons it is also compared with general-purpose LLMs.

Mid-frequency here means sub-second decisions with second-to-minute horizons. True high-frequency trading (microseconds, co-located servers) is out of scope.

    执行与计价Execution & valuation

      统计方法与判定标准Statistics & pass criteria

      • 置信区间：相邻决策点只隔 300 ms，预测窗口高度重叠，不能视为独立样本。采用分块自助法（快档 60 秒一块、慢档 15 分钟一块，整块重抽 2000 次，固定随机种子）。看板上的区间为 Wilson 近似，仅供参考。
      • 配对比较：Jev 与各对照在同一批决策点上逐点比较，差值的区间整体低于 0 才算显著落后。
      • 多重比较校正：与 8 条对照逐一比较时采用 Bonferroni 校正（单次 α = 5% / 8），避免「比得越多、越容易误判」。
      • 预先锁定：计划时长在开始时写入记录，中途不依据结果决定是否停止；提前停止或中断会在结果中注明。
      • Confidence intervals: ticks are 300 ms apart, so forecast windows overlap heavily and are not independent. We use a block bootstrap (60 s blocks for the fast tier, 15 min for the slow tier, 2,000 resamples, fixed seed). Dashboard intervals are Wilson approximations for reference only.
      • Paired comparison: Jev and each baseline are compared on the same ticks; Jev is significantly behind only if the whole interval of the difference is below 0.
      • Multiple comparisons: comparisons against the 8 baselines use a Bonferroni correction (α = 5% / 8 each).
      • Pre-registration: the planned duration is recorded at start and the run is never stopped based on results; early stops and interruptions are flagged in the results.

      局限Limitations

      • 只覆盖一个市场（币安 BTCUSDT 永续），结论不外推到其他品种和交易所。
      • 从中国大陆调用 Jev 存在跨境网络延迟（P50 约 350–800 ms），因此 Jev 的准确率按响应返回时刻计算；看板同时给出按发问时刻计算的理想口径。
      • 挂单模拟看不到真实队列位置，只能给出乐观、保守两个边界。
      • 对照策略之间存在相关性（如 QI 与 DI），不应视为相互独立的证据。
      • 累计收益与 markout 用于横向比较判断质量，不代表可直接运行的策略收益。
      • 9/25 修正记录：此前两场（20260924_2300、20260925_0815）发给 Jev 的挂单深度按「距中间价 10 / 25 / 50 bps」统计，而 BTC 的 20 档盘口只覆盖约 0.4 bps，三组数值相同且失真；输入说明也只点名了成交字段。已改为按档位统计、完整列出全部字段，从 20260925_1004 起的场次使用修正后的输入。前两场仅作原版口径参考。
      • One market only (Binance BTCUSDT perpetual); results do not generalise to other assets or venues.
      • Jev is called from mainland China with cross-border latency (P50 ≈ 350–800 ms), so its hit rate is scored from the moment the answer arrives; the dashboard also shows the idealised score from the moment of asking.
      • The maker simulation cannot see real queue position, so only optimistic and conservative bounds are given.
      • Baselines are correlated (e.g. QI and DI) and should not be read as independent evidence.
      • Cumulative P&L and markouts compare signal quality; they are not the returns of a deployable strategy.
      • Correction log (Sep 25): the first two runs (20260924_2300, 20260925_0815) gave Jev depth measured "within 10 / 25 / 50 bps of mid", but 20 levels of the BTC book span only ~0.4 bps, so all three values were identical and misleading; the input description also named only the trade-flow fields. Depth is now cumulative over the best 1 / 5 / 20 levels and every field is described; runs from 20260925_1004 onward use the corrected inputs. The first two runs are kept as reference only.
