# EP007 · 用 GLM-5.3 搭一套 A 股投研工作流

> 每天早上八点,手机上收到一条两百字的自选股简报。想看细节点开完整报告,
> 想看几个 AI 当时怎么吵的,点开辩论回放。
>
> 底座是开源的多 Agent 交易框架,外面补的四个模块基本是 AI 写的,前后不到两天。

**视频**:〔B站链接〕 · 〔YouTube 链接〕

## 这期干了什么

| | |
|---|---|
| **底座** | [TradingAgents-CN](https://github.com/hsliuping/TradingAgents-CN) —— LLM 驱动的多 Agent 交易框架,A 股适配版 |
| **模型** | 智谱 GLM-5.3 |
| **编程工具** | ZCode |
| **产出** | `studio/` 四个模块:digest / notify / replay / compare |

原生 TradingAgents 只是个**分析工具**,不是能自动运转的流水线。中间差四样:

1. 报告好几千字,开盘前读不完 → **digest**:压成两百字
2. 跑完不通知你,得自己开网页等 → **notify**:推到飞书等 5 个渠道 + 定时
3. 换模型只能手动改配置一个个跑 → **compare**:一条命令跑多个模型出对比表
4. Agent 辩论只能在 UI 里看,不清晰 → **replay**:渲染成群聊回放

补齐这四样,分析工具才变成工作流。

## 怎么自己跑一遍

完整步骤见 [`RUNBOOK.md`](RUNBOOK.md),概括是四步:

1. **装底座** —— 把 [`prompts/01-install.md`](prompts/01-install.md) 丢给 ZCode,让它读 README 用 Docker 部署
2. **接模型** —— Web UI 里加自定义厂家,厂家 ID 填 `zhipu`,模型名 `glm-5.3`
3. **跑一只票** —— 分析深度拉满,等五六分钟出报告
4. **装 studio** —— 直接用 [`studio/`](studio/) 里的代码，或者把 [`prompts/03-design-studio.md`](prompts/03-design-studio.md) 丢给 ZCode 自己生成一遍

**前置**:Docker Desktop、一个智谱 API Key、一个 Tushare Token(免费额度够用)。

## 几个踩过的坑

**厂家 ID 必须填 `zhipu`,不能填 `glm`**
枚举里两个都有,但只有 `zhipu` 在适配器表里注册了。填 `glm` 的话 key 认得出来,
创建 LLM 实例时查不到适配器,会挂。

**`.env` 优先级高于数据库里的厂家配置**
如果 `.env` 里已经有 `ZHIPU_API_KEY` 且不是 `your_xxx` 占位符,
Web UI 里填的 key 会被它覆盖。会出现"测试通过但分析报错"的怪现象,
看后端日志里打的是「使用 .env 文件中的」还是「使用数据库厂家配置的」就知道。

**Docker 部署流程缺一步:数据库里没有默认用户**
第一次登录会提示用户名密码错误。官方文档给了默认账号密码,但数据库里那条记录不存在,
需要调初始化脚本创建管理员。视频 04:33 那段就是在处理这个。

**A 股只能选三个分析师**
数据源不覆盖社交媒体,所以情绪分析师那一路开不了。

## 关于模型能不能信

这套东西的**工程部分**——读项目、改代码、写插件——GLM-5.3 干得可以,
整套 studio 基本是它写的,我做的是提需求、看它改、复制报错、点确认。

但它出的**分析报告不能直接当结论用**。测试过程中出现过硬伤,
比如把大小关系说反、下一句又自相矛盾。这不是某一家模型的问题,
是现在所有大模型的通病——**你得有办法验证它,而不是让它替你决定**。

`replay` 那个对照视图就是干这个用的:把多空双方对同一话题的表述并排放,
矛盾自己就露出来了。
