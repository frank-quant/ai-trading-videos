# 04 · 逐个实现四个模块

**视频 06:40 起** · 设计确认之后,**一个模块一个 prompt**。

一口气要四个,大概率给你一堆跑不起来的骨架。

## digest

```
设计我认可。先写 digest 这个模块。

输入是一份完整分析报告，输出：
- tldr：三行以内的核心结论
- signals：关键买卖信号，每条一句话
- risks：风险点，每条一句话

压缩用 LLM 做，模型走项目现有配置，不要写死。
提供两种输出：dict 给程序用，markdown 给人看，markdown 版控制在 200 字左右。

写完拿一份真实报告测一遍，把压缩前后的字数打出来给我看。
```

## notify

```
接着写 notify。

设计一个统一的 channel 接口，实现五个渠道：
飞书、企业微信、钉钉、Telegram、邮件。

飞书这个先做完整：用交互式卡片，卡片里要有标题、评分、
digest 出来的 TLDR、风险点，底部一个"查看完整报告"的按钮。

配置走环境变量，每个渠道可以单独开关。
推送失败要有重试和日志，不能因为推送挂了影响主流程。

我已经把 webhook 放到环境变量 FEISHU_WEBHOOK_URL 了，
写个测试脚本推一条到我的飞书群，我看效果。
```

⚠️ **卡片里那个链接,手机上要能点开。** 服务跑在本地的话手机访问不了 localhost,
需要内网穿透或者部署到有公网 IP 的地方。录之前拿手机真点一次。

## replay

```
写 replay。把 Agent 辩论过程渲染成 HTML。

两个视图：
1. 聊天流：每个 Agent 一个 emoji 头像，气泡带时间戳，
   看多的在左边看空的在右边，每轮辩论之间有分隔条
2. 正反打：把双方的分歧点两两配对，同一个话题左边多头怎么说、
   右边空头怎么说

生成单文件 HTML，CSS 和 JS 全部内联，不引用任何外部资源，
这样我可以直接发给别人。
```

⚠️ **气泡里别放原文。** Agent 每条发言两千多字,塞进聊天气泡比读原报告还累。
让它从原文里提炼一两句"金句"放气泡,原文折叠起来点开看。

## compare

```
最后写 compare。

一条命令，同一只股票、同一个日期、同一套配置，只换模型，并行跑：
  studio compare 002594 --models glm-5.3,deepseek-v4,kimi-k3

采集这些硬指标：
1. 端到端耗时
2. 总 token 消耗
3. 辩论实际跑了几轮
4. 是否中途报错或超时
5. 上下文遗忘：后面的 Agent 有没有无视前面已经说过的结论
6. 数字幻觉：报告里的财务数字和数据源对不对得上
7. 角色串戏：让它演基本面分析师，有没有跑去聊技术指标

终端要有实时进度，最后输出一张对比表。

⚠️ 测不准的指标标"未测"，不要猜一个数填上。
```
