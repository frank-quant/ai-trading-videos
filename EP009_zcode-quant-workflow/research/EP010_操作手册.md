# EP010 操作手册

先将本文件所在的research文件夹整体复制到公开仓库以外的新目录，例如ep010-research。以下操作均在这个独立副本中执行；不要复制旁边的results目录。公开仓库本身会忽略研究运行产物，不能用它代替独立研究的阶段版本记录。

在独立副本中打开ZCode或具有文件与代码执行能力的AI工具。确认当前工作目录是该副本的根目录；将本步提示词整体复制执行，核对产物后再进入下一步。ZCode中的`/workflow`是调用入口；其他工具需自行安排相同职责与审核过程，不能把提示词当作普通聊天即可完成的程序。

本工程提供引擎、测试、零件库和八步任务，启动状态为空。AI搜索具有随机性，不能保证生成相同策略或得到非零达标数量。运行前不要查看 ../results/；若已看过，声明这是公开历史案例上的再研究。

## 环境准备

本机需安装Git。在独立副本中初始化本地研究仓库，保存初始状态：

```powershell
git init
git add -A
git commit -m "研究初始状态"
```

每个阶段提示词中的`git commit`之前，先执行`git add -A`，将该阶段的配置、笔记、台账、报告和数据清单加入提交。附带的`.gitignore`排除原始行情、凭据、虚拟环境和缓存；研究输出仅作本地版本记录，不自动推送。Git若提示缺少提交身份，先按提示设置本地仓库的姓名和邮箱。

推荐64位Python 3.14，与案例使用版本一致；依赖已在requirements.txt锁定。先建本地环境：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python tools/check.py
```

Linux/macOS激活命令为`source .venv/bin/activate`。全量行情和面板需要较多内存；从2个worker起实测，再决定并发。案例使用约62GB内存机器，并发数不能直接照搬。

本地设置环境变量TUSHARE_TOKEN，或在当前终端隐式输入（不把值写进命令历史）：

```powershell
$secureToken = Read-Host 'Tushare Token' -AsSecureString
$env:TUSHARE_TOKEN = [System.Net.NetworkCredential]::new('', $secureToken).Password
Remove-Variable secureToken
```

Token不能放进提示词、配置、报告或Git。环境变量仅供本地下载进程读取。

## 使用口径

下面集中列出八步执行提示词，按顺序逐段复制执行，核对产物后再进入下一步。提示词正文与指定手册保持一致。

- 当前工作目录为本文件所在的独立研究副本根目录；路径均相对本目录。
- “至今”统一限定为本工程固定截止日2026-09-30，不能随系统日期延长。
- 提示词中的硬件与吞吐目标为参考配置，执行前按rules.md第12章核对本机资源。
- 从空台账、空候选、空笔记开始，不导入附带案例结果；不存在的历史作废组不另行创建。
- 研究角色按rules.md、profile.md与当前步骤开展任务，不主动push。

| 数据段 | 区间 | 用途 |
|---|---|---|
| 搜索期 | 2014-01-01至2022-12-31 | 生成、回测与迭代 |

| 测试集 | 2025-01-01至2026-09-30 | 名单与组合规则锁定后的评估 |

## 第 1 步：下载数据（上限 8.0h，过夜）

```
从 Tushare Pro 下载本项目要用的全部数据。先读 rules.md（重点第 1 节时间切分、7.5 搜索范围、7.6 数据源）和 profile.md，再动手。不许修改 rules.md、profile.md。

【Token】只从环境变量 TUSHARE_TOKEN 读取，不许写进任何文件、日志或打印输出；读不到就报错退出。

【限流】单进程，禁止多进程多线程；每次接口调用之间 sleep 0.45 秒；遇到权限或频次错误、或连续 3 次失败，就把进度写进 data/_fetch_state.json 后退出，不许重试轰炸；每 50 个单位存一次进度，支持断点续传。预计要跑 6–8 小时，这是预期行为，不要为了赶时间提高并发。

【落盘与切分】
- 切分日 2024-12-31：**2024-12-31 及以前写 data/raw/，2025-01-01 及以后写 data/sealed/**
- 封存部分在内存里算完 SHA256 直接落盘，**写完不读回、不打印、不做任何统计**
- 格式用 parquet；同一接口的结果合并成一个文件（daily.parquet、adj_factor.parquet…），不要一只股票一个文件
- data/ 下只增不删

【股票池】
用 index_weight 拉三个指数 2013-12 起每个月末的成分：000300.SH（沪深300）、000905.SH（中证500）、000852.SH（中证1000），存 index_members.parquet。
所有出现过的成分股合集 = 要下载个股数据的股票列表（**含后来调出、退市的**）。

【个股数据】区间 2013-01-01 至今
- daily（不复权 OHLC、pre_close、vol、amount、pct_chg）
- adj_factor（复权因子）
- daily_basic（turnover_rate、pe_ttm、pb、ps_ttm、total_mv、circ_mv）
- stk_limit（涨跌停价）
- suspend_d（停牌）
- namechange（历史名称，用于判断当日是否 ST）
- fina_indicator（**务必保留 ann_date 和 end_date**）
- forecast、express（业绩预告与快报，**务必保留 ann_date**）
- index_member_all（申万行业，保留纳入和剔除日期）
- stock_basic（list_status 取 L、D、P 三次合并，含 list_date、delist_date）

【资金面】按交易日拉，2014-01-01 至今
- top_list、top_inst（龙虎榜，按 ann_date 对齐）
- margin_detail（两融明细，按披露日对齐）
- hk_hold（北向持股，2014-11 沪股通开通后才有，单独存文件）
- moneyflow_hsgt（陆股通整体资金流）

【ETF 与日历】
- fund_daily、fund_adj：510300.SH、510500.SH、518880.SH、511010.SH（fund_adj 没权限就只存 fund_daily 并在报告里写明）
- trade_cal：SSE，2013 年至今

【完成后】
- 生成 data/MANIFEST.json：每个文件的行数、日期范围、SHA256、来源接口
- 生成 reports/data_check.md，**只统计 data/raw/**：
  · 股票池总数、每月成分数是否都是 300 / 500 / 1000
  · 每只股票相对交易日历的缺口天数（停牌除外）
  · 复权连续性自检：close × adj_factor 的日涨幅 vs pct_chg，偏差超 0.5% 的列出来
  · 财务、预告、快报、龙虎榜的公告日相对报告期的滞后天数分布
  · 两融、北向、行业数据的起止日期与覆盖率
- git commit（data/ 下的 parquet 不进 git，MANIFEST.json 进）
```

**检查：**

- [ ] data/MANIFEST.json完整，原始数据不进公开仓库。
- [ ] raw日期不晚于2024-12-31；sealed从2025-01-01开始，准备阶段不读取其表内容。
- [ ] reports/data_check.md只检查raw，记录股票池、接口缺口与实际数据覆盖。

## 第 2 步：设定日期口径 + 性能优化（上限 3.0h）

```
/workflow
把引擎的日期口径设定为 rules.md 第 1 节的三段切分，并做性能优化；由独立审计 Agent 验收。不许修改 rules.md、profile.md、data/。

【日期口径：5 处必须按 rules.md 第 1 节设定，漏一处整轮作废】
| 文件 | 要设定的值 |
|---|---|
| engine/guard.py | 封存起点 20250101、raw 上界 20241231 |
| engine/funnel.py | 搜索 20140101/20221231、验证 20230101/20241231；文件内两处区间断言同步 |
| engine/compare.py | 搜索 20140101/20221231 |
| engine/backtest.py | 默认区间 20140101/20221231 |
| 抓数脚本 | 落盘切分日 20241231 |
设定后在 reports/audit_engine.md 里逐行列出当前值。

【性能优化】
硬件：AMD Ryzen 9 9900X，12 物理核 / 24 逻辑核，内存 62 GB。
先 profile 一个真实配置的耗时分布（面板加载 / 零件取值 / 撮合循环 / 台账写入），写进 reports/perf_report.md，再决定优化点。
允许的手段：
- 零件取值预计算一次、跨配置共享（收益最大）
- 面板只加载一份，worker 之间共享内存或 memmap，禁止每进程各加载一遍
- worker 设 12~16，并把 OMP_NUM_THREADS / MKL_NUM_THREADS / OPENBLAS_NUM_THREADS 固定为 1
- 撮合循环向量化；已在台账且有 run 目录的结果直接复用
禁止：放宽浮点容差、抽样日期、截断历史、降低精度——任何以精度换速度的做法。

【审计 Agent（独立于写代码的 Agent）】
- 封存边界专项（最高优先级）：check_date_range 对 2024-12-31 放行、对 2025-01-01 抛异常；data/raw 最大日期 ≤ 2024-12-31、data/sealed 最小日期 ≥ 2025-01-01
- 逐位回归：随机抽 50 个配置（覆盖规则型与打分型），优化前后全部指标逐位一致，差一位即失败
- 重跑 tests/newspaper_test.py（撕报纸）、tests/sealed_test.py（封存）、engine/selftest.py，全部通过
- 结论写入 reports/audit_engine.md

【测速与决策】
优化后重测单次回测耗时与并行吞吐，按本手册第 4、5、6 步的任务量重新估算，写进 reports/perf_report.md。
目标：单次回测 20 秒以内，16 worker 吞吐约 1.2 秒一条。
加速比不足 2 倍、或估算仍超各步上限，立刻停下来报告，不要开跑。
```

**检查：**

- [ ] reports/audit_engine.md与reports/perf_report.md已生成。
- [ ] 日期边界和独立测试通过；如有优化，50个配置逐位回归通过。
