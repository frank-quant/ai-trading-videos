## 8. 技术指标与信号（`indicators.csv` / `signals.csv` / `technical_snapshot.md`）

### 8.1 计算基准

全部指标基于 `prices.csv` 的**前复权收盘价**计算（前复权锚定 2026-10-23），保证跨除权日的价格连续性。

| 指标 | 口径 |
|---|---|
| SMA5 / SMA20 / SMA60 | n 日简单移动平均 |
| EMA12 / EMA26 | 以首 n 日均值初始化，之后 α=2/(n+1) 递推 |
| MACD | DIF = EMA12 − EMA26；DEA = EMA9(DIF)；柱 = 2×(DIF − DEA)（通达信/同花顺口径） |
| RSI14 | Wilder 平滑，初始值为前 14 期涨跌均值 |
| 均线斜率 | 5 日窗口日均变化量：`(MA[t] − MA[t−5]) / 5`，同时给出 %/日 版本 |
| 均线排列 | 多头排列 / 空头排列 / 短多长空 / 短空长多 / 交汇纠缠 |

## 9. 教学回测（SMA5 × SMA20 交叉，`Ledger_Gross.csv` / `Ledger.csv`）

### 9.1 交易规则

| 项 | 规则 |
|---|---|
| 入场 | SMA5 上穿 SMA20（金叉），**信号次日开盘**全仓买入 |
| 出场 | SMA5 下穿 SMA20（死叉），**信号次日开盘**清仓 |
| 方向 | 仅做多，**不做空**；死叉时若已空仓则只记录信号不交易 |
| 预热 | 前 59 根K线不交易（此时 SMA60 尚未成立，信号本身也不存在） |
| 样本末 | **不强制平仓**——期末持仓按最后一根K线收盘价盯市 |
| 初始资金 | 1,000,000 元（教学设定） |
| 份额 | 允许小数份额（买入时以 `资金 ÷ (成交价 × (1+费率))` 计算，成交后现金恰为 0） |
| 价格口径 | `prices.csv` 的**前复权**开盘价成交，与信号所用的前复权收盘价同口径 |

**成本口径**：`Ledger_Gross.csv` 零成本；`Ledger.csv` 单边 **0.075%**，**不含印花税、不含过户费**。
买入手续费 = 买入金额 × 0.075%，卖出手续费 = 卖出金额 × 0.075%，从对应现金中扣除。

### 9.2 账本字段

`date`（交易日）｜`is_warmup`（预热标记）｜`open` / `close`｜`signal`（该日收盘产生的信号：none / golden_cross / death_cross）｜`action`（该日开盘的动作：NONE / BUY / SELL / IGNORED）｜`exec_date`（执行日期 = 信号次一交易日）｜`fill_price`（成交价 = 该日开盘价）｜`shares`（**期末**持仓股数）｜`position_value`（期末持仓市值）｜`cash`（期末现金）｜`fee`（当日费用）｜`cum_fee`（累计费用）｜`nav`（**每日净值**，收盘口径）｜`daily_return`｜`cum_return`｜`peak_nav`｜`drawdown`

> 行内 `signal` 与 `action` 相差一行是刻意设计：信号在**收盘后**才成立，成交在**次日开盘**完成，两者在同一行里永远不会同时出现，以杜绝前视偏差。

> 3. 费用累计 56,521.26 元 = 初始资金的 5.65%，把累计收益从 +48.69% 压到 +44.30%。
> 4. 未做**样本外检验**、未做参数敏感性检验、未考虑滑点与冲击成本、未考虑涨跌停无法成交的情形——真实结果大概率更差。

### 9.5 已知限制

1. **成交假设偏乐观**：按开盘价全额成交，未考虑开盘集合竞价的可成交量、涨跌停封板无法成交、流动性不足导致的冲击成本。
2. **不含停牌与涨跌停**：本样本该股未出现停牌，但规则未显式建模。
3. 前复权价格成交意味着**账面金额不等于真实可交易金额**；收益率序列正确，绝对金额仅为教学口径。
4. 单笔全仓进出、**无止损/无仓位管理/无持有期约束**，实盘不可照搬。

**年化收益口径（统一约定）**：

```
年化收益 = (期末净值 / 初始资金) ^ (252 / (N − 1)) − 1
```

其中 `N = 822` 为净值观测点数，`N − 1 = 821` 为日收益期数（首日建仓不产生收益期）。
Python 侧 `scripts/metrics.py`、`scripts/backtest.py` 与 Excel 侧 `Summary!B7:E7`
（公式 `=(B5/InitCapital)^(AnnualDays/(COUNTA(...)-1))-1`，`AnnualDays` 为 Assumptions 里的具名参数 252）
**使用完全相同的口径**，两侧年化收益可逐位对上。

> 口径说明：早期版本 Python 侧曾用 `252 / N`（把观测点数当收益期数），Excel 侧用 `252 / (N−1)`，
> 造成含费策略年化相差 0.000153。已统一为标准收益期口径 `252 / (N − 1)`，
> Python 侧 `metrics.py` / `backtest.py` 已同步修正，`metrics.csv` 与 `raw/backtest_summary.json` 已重新生成。

## 12. Excel 联动模型（`moving_average_analysis.xlsx`）

### 12.1 设计原则：Formula-first

**除 `Assumptions` 之外，工作簿里没有任何硬编码数字。** 所有指标、信号、账本、汇总、自检
全部写成活的 `=` 公式，指向 `Assumptions` 里的具名参数与 `Prices` / `Prices_Bench` 的原始行情。
改动 `Assumptions` 中任一参数（均线周期、费率、预热行数、初始资金……）后，
`Indicators` → `Ledger` / `Ledger_Gross` → `Summary` → `QA` 会逐层自动重算。

| 工作表 | 性质 | 内容 |
|---|---|---|
| `Assumptions` | **输入区**（蓝字 + 黄底 + 边框） | 21 个具名参数：初始资金、初始持股、SMA5/20/60、EMA12/26、DEA9、RSI14、斜率窗口 5、单边佣金 0.075%、印花税 0、过户费 0、年化交易日 252、预热行数 59、起止日期、标的与基准代码名称 |
| `Prices` | 原始数据（蓝字＝输入） | 822 行个股前复权 OHLCV |
| `Prices_Bench` | 原始数据（蓝字＝输入） | 822 行沪深300 价格指数 |
| `Indicators` | 公式 | SMA5/20/60、EMA12/26、MACD DIF/DEA/柱、RSI14、三条均线斜率、均线排列状态、技术评分与评分档、预热标记；S/T 列为 RSI 平滑的隐藏辅助列 |
| `Ledger_Gross` | 公式 | 零成本账本（17 列） |
| `Ledger` | 公式 | 含费账本（17 列），费率取自 `Assumptions` |
| `Summary` | 公式 | A4:E16 四列指标对照表、A19:B20 费用分解专项、A23:A25 公式自动生成的结论文本；H:X 为净值/回撤隐藏辅助列 |
| `QA` | 公式 + 留档 | 行 5~19 为 15 项**活公式自检**（改参数后自动重检并输出 PASS/FAIL）；行 21 起为 `qa_check.py` 的 47 项独立复核留档 |

| 项 | 结果 |
|---|---|
| 工作表顺序 | `Assumptions, Prices, Indicators, Ledger, Ledger_Gross, QA, Summary, Prices_Bench` ✅ |

| 错误单元格（`#REF!` `#DIV/0!` `#VALUE!` 等） | **0** |
| 与 CSV 逐项比对 | **57/57 项一致** |

### 12.3 工作簿建设过程中修正的 4 个真实缺陷

| # | 缺陷 | 现象 | 修正 |
|---|---|---|---|
| 1 | `OFFSET` 参数个数错误 | EMA 种子写成 `OFFSET(Prices!$E$2,0,EmaFast,1)`，把「行偏移」当成了「列偏移」 | 改为 `OFFSET(Prices!$E$3,0,0,{per},1)` |
| 2 | 斜率缺类型保护 | Excel 中 `"" > 0` 为 TRUE，导致预热期斜率参与评分，与 Python 语义不符 | 斜率公式与评分项均加 `NOT(ISNUMBER(...))` / `ISNUMBER(...)` 保护 |
| 3 | **整表行号错位 1 行** | 表体数据从第 3 行开始，公式却按第 2 行起算 | 统一定义 `FIRST=3 / LAST=824`，13 处 `ROW()-2` 改为 `ROW()-3`；DEA 种子锚点改 `H$3`；RSI 的 INDEX 区间改为行 4..RsiLen+3 与 3..RsiLen+2 |
| 4 | `COUNT` 统计文本日期列返回 0 | `Summary!B14:E14` 出现 `#DIV/0!`、年化收益变成 −1 | `COUNT` 改为 `COUNTA` |

错误单元格数量演进：**22,934 → 18,874 → 4 → 0**。

### 12.4 与 Python 侧的一致性

Excel 与 Python 走的是两套独立实现（Excel 用公式、Python 用脚本），
最终在关键指标上逐位对齐：期末净值、累计收益、年化收益、最大回撤及其峰值/谷底日、
交易次数、持仓天数与占比、两项费用口径，**全部一致**。
唯一一次不一致出现在年化收益上（Python `252/N` vs Excel `252/(N−1)`），
已按 §10.1 的口径统一为 `252/(N−1)` 并两侧同步修正。
