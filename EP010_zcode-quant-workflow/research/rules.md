# A股策略研究规则

> 本文件定义研究范围、数据边界、交易模型、筛选标准与交付要求。执行前由研究负责人确认，与交易者画像 `profile.md` 一起提交保存。执行角色按规则开展研究，不自行修改时间区间、交易假设或筛选门槛。

## 1. 时间切分与数据隔离

| 数据段 | 区间 | 用途 |
|---|---|---|
| 搜索期 | 2014-01-01 ～ 2022-12-31 | 提出假设、生成配置、回测与迭代 |
| 验证期 | 2023-01-01 ～ 2024-12-31 | 验证表现、相关性与统计检验，并参与入围排序 |
| 封存期 | 2025-01-01 ～ 研究截止日 | 名单与组合规则锁定后的最终评估 |

- 研究截止日在数据准备阶段确定，记录到 `data/MANIFEST.json`。后续计算使用已确定的实际数据截止日，不随系统日期自动延长。
- 搜索角色仅可使用搜索期数据，不读取验证期、封存期的内容或表现。
- 验证期用于第6～8层和入围评分；参与选择的验证结果不得解释为独立的最终检验。
- 封存期不参与开发、调参和入围选择，名单与组合规则锁定后才能评估。
- 搜索期和验证期原始数据放在 `data/raw/`，封存期放在 `data/sealed/`，切分日为2024-12-31。
- 引擎仅在项目根目录存在 `OPEN_SEALED` 文件时允许读取封存数据。该文件由研究负责人在最终评估时创建，评估结束后立即删除。
- 开封前提交保存候选名单、配置哈希、组合定义及代码状态；开封后不根据结果调整参数或更换评估对象。

## 2. 撮合与可交易约束

- T日收盘形成信号，T+1交易日开盘执行。
- 涨跌停价格使用 Tushare `stk_limit` 的当日 `up_limit`、`down_limit`：开盘价不低于涨停价时不能买入，不高于跌停价时不能卖出，未成交订单按执行规则顺延。
- 停牌以 `suspend_d` 为准，停牌当天不能买卖。
- ST状态按 `namechange` 的历史名称区间判断；当日名称包含 ST 或 *ST 的股票不进入可买入股票池，不使用当前名称回看历史。
- 剔除上市不满250个交易日的股票，上市日期使用 `stock_basic.list_date`。
- 跨日收益使用后复权价 `close × adj_factor`；开盘价与前收盘价等日内比例使用不复权价格。
- 估值与预算仅使用决策时点之前可知的价格。开盘下单时，持仓按上一交易日收盘价估值。
- 停牌、涨跌停、退市和未成交订单的处理必须写入实现说明并接受测试，不以事后价格替代不可成交价格。

## 3. 成本模型

| 项目 | 回测费率 |
|---|---|
| 佣金 | 买卖双边各0.025% |
| 印花税 | 仅卖出；2023-08-28之前0.1%，当日及以后0.05% |
| 滑点 | 买卖单边各0.1% |

策略与股票池等权基准采用一致的成本口径。报告说明费用计提、滑点和成交约束，不将固定滑点解释为完整市场冲击模型。

## 4. 仓位与交易者画像

- 不融资、不做空、不加杠杆。
- 单只股票仓位上限10%，采用等权配置。
- 规则型最多同时持有10只股票。
- 打分型目标持有30只股票，支持周度或月度调仓。
- 持有频率、资金结构及回撤容忍度以 `profile.md` 为准；执行前确认其与本文件一致。

## 5. 筛选、分级与入围

### 5.1 指标定义

- **股票池等权基准**：当日股票池内可交易、非ST成分股等权，按同一模型扣成本。
- **年化收益**：日收益逐日复利后，按每年250个交易日折算。
- **年化超额**：策略年化收益减去基准年化收益，报告时用百分点表示。
- **日超额收益**：策略日收益减去基准日收益。
- **超额净值**：日超额收益按 `∏(1 + 日超额收益)` 累乘。
- **信息比率IR**：日超额收益均值除以日超额收益标准差，再乘以 `√250`。
- **超额最大回撤**：超额净值相对其历史高点的最大跌幅，筛选时比较其绝对值。
- 策略自身的夏普、绝对最大回撤照常报告，不代替本章的超额收益筛选条件。

### 5.2 八层筛选条件

| 层   | 条件                                            | 数据段     |
| --- | --------------------------------------------- | ------- |
| L1  | 规则型交易不少于100笔，买卖各算一笔；打分型周度调仓不少于300期、月度调仓不少于80期 | 搜索期     |
| L2  | 扣成本后年化超额大于0                                   | 搜索期     |
| L3  | IR大于0.4，且超额最大回撤小于30%                          | 搜索期     |
| L4  | 9个完整年份中，至少6年年度超额大于0                           | 搜索期     |
| L5  | 可移动参数调整一档后，至少70%的相邻配置仍通过L1～L4                 | 搜索期     |
| L6  | 验证期扣成本后年化超额大于0                                | 验证期     |
| L7  | 与已保留策略的日超额收益相关系数小于0.7                         | 搜索期＋验证期 |
| L8  | 按本组试验总数N计算的DSR大于0.95，且日超额收益t值不小于3             | 搜索期＋验证期 |

- L1～L4采用累计通过口径，后层仅评价前序条件通过的基础配置。
- L5覆盖全部通过L1～L4的基础配置，不按入围分截取部分候选。
- 邻域配置为检验探针，名称中含 `__`。探针正常回测、记账并计入本组N，但不自行参与L5～L8、不递归生成邻域、不参与入围排名。
- 邻域按事先定义的参数档位生成；报告记录被移动参数、邻居数及通过比例。没有可移动参数时须注明其检验范围，不以空邻域证明全面稳健。
- 计算报错、任务缺失和实际指标不达标分别记录。原定检验任务未成功完成时，不能声称完成了全部检验；资源错误可在原配置、原区间下恢复，记录全部执行尝试。
- L7在AI与随机对照的L6幸存者构成的全局池中去重，记录保留顺序、相关阈值与剔除原因，报告各组计数时注明同一个池。
- L8基于日超额收益序列，试验数按第6章计算。
- 组合绝对最大回撤在第5.5节检验，不用于替代单个策略的超额回撤门槛。

### 5.3 分级

| 等级 | 含义 |
|---|---|
| 达标 | 通过全部八层 |
| 入围 | 按第5.4节规则进入本组研究名单，但未通过全部八层 |
| 落选 | 未进入本组研究名单 |

- 每组输出3个研究候选，达标者优先占名额，不足部分按入围分补充。
- AI的A、B两路合并选3个；主随机对照和每组随机对照各自选3个。
- 入围不等于有效。每条候选同时报告等级、入围分、未通过层和未执行层。
- 仅AI的3个候选和主随机对照的3个候选进入封存期评估；其余随机组用于对照分布。

### 5.4 入围评分

1. 硬性资格：通过L1，且搜索期、验证期的年化超额均大于0。
2. 入围分取两段IR中较低者：`min(搜索期IR, 验证期IR)`。
3. 同分时，按两段超额最大回撤绝对值中较大者排序，较小者优先。
4. 满足硬性资格的候选不足3个时，按搜索期IR补足，标注“补位：验证期未通过”。若连L1资格都不足，则按搜索期年化超额补足，并标注“未过L1，交易样本不足”。
5. 补位对象仅称本组候选，不称达标策略；缺少的评估结果明确标记。
6. 入围名单内部不额外执行L7去重，但必须报告其日超额相关性。

### 5.5 组合层

- 卫星部分：本组3个入围候选等权。
- 底仓部分：沪深300 ETF在200日均线上方时持有，跌破时切换至黄金ETF。
- 组合资金结构：底仓60%、卫星40%，与 `profile.md` 一致。
- AI与主随机对照各自构建组合，采用相同执行和换腿成本口径。
- 搜索、验证、封存三段分别报告组合年化收益、绝对最大回撤及相对沪深300 ETF买入持有的年化差。
- 组合最大回撤小于25%为检验项，不是筛选或换名单的依据。
- ETF复权或其他必要数据不足以覆盖某段时，明确标记该段不可用；可得子区间单独列示，不替代完整区间。

## 6. 台账与试验数

- 每次执行均追加到 `ledger/ledger.csv`，包含基础配置、邻域探针、失败任务和恢复重试，不删除或改写已有行。
- 每行至少记录时间、配置名、配置哈希、group、回测起止日、状态、交易数、收益风险指标、漏斗标记及错误说明；配置哈希也可关联到同次运行的 `summary.json`。
- `group` 使用 `A`、`B`、`monkey_<种子>`、`example`、`test`。
- 同一任务由 `(group, config, start, end)` 标识，判断当前执行状态时取最新记录，历史记录保留。
- AI的N等于A、B组全部台账行数之和，包含错误与重试及邻域探针。
- 每组随机对照的N仅统计自己的全部台账行，包含自身邻域探针和重试。
- `example`、`test`不计入研究组N。
- 每次判定保存N的统计时点、范围和分组方式。此N是预设记账口径，不直接等同于有效独立试验次数。
- 成功状态须能对应同配置、同区间的有效结果文件，不能仅凭任务结束或文件夹存在判断成功。

## 7. 参数档位

| 参数类型 | 允许档位 |
|---|---|
| 窗口长度，交易日 | 3、5、10、20、60、120、250 |
| 百分比阈值 | 1%、2%、3%、5%、8%、10%、15% |
| 倍数阈值 | 0.5、0.8、1.0、1.2、1.5、2.0 |
| 持有天数上限 | 3、5、10、20、40、60 |
| 止损 | 无、5%、8%、10% |
| 打分型持仓数 | 30 |
| 调仓频率 | 周度、月度 |
| 市值分档 | 按当日流通市值分位划分5档 |
| 截面分位阈值 | 前10%、20%、30%；后10%、20%、30% |

表中档位约束对应类型参数，不能用其他数值替换。打分因子权重写入配置并留存，不将权重与窗口、百分比或倍数阈值混为同一种档位参数。

### 7.5 搜索范围

| 项目 | 范围 |
|---|---|
| 股票池 | 沪深300、中证500、中证1000历史成分并集，按当日成分确定 |
| 基准 | 当日股票池可交易、非ST成分等权 |
| 指标类别 | 量价、估值、规模、财务、业绩预告与快报、申万历史行业、市场状态、龙虎榜、融资融券、北向持股 |
| 中性化处理 | 打分型支持行业内排名、市值5档内排名，两个开关独立控制，报告实际启用项 |
| 持有期 | 规则型3～60个交易日；打分型周度或月度调仓 |
| 搜索规模 | A、B各至少6轮，每轮100～150个基础配置 |
| 随机抽样范围 | 与AI使用同一可用零件库和对应参数档位 |

- 财务、业绩预告、快报及事件数据按实际公告或披露时点可用，不按报告期末日期提前使用。
- 行业归属按成分纳入、剔除日期判断；数据不支持历史变迁时，明确记录近似方法和覆盖限制。
- 两融、北向等资金面按实际披露时点对齐；数据所属日与公布日分别识别。
- 缺失数据不直接填成0，处理方法在零件说明中定义，并通过测试。
- 新零件须通过未来数据截断测试和独立审核后才能使用。

### 7.6 数据源与数据准备

数据源为 Tushare Pro。首次执行按以下接口准备数据，具体区间须覆盖搜索、验证和封存期，以及指标所需的前置窗口。

| 数据类别 | 接口与关键内容 |
|---|---|
| 历史指数成分 | `index_weight`：000300.SH、000905.SH、000852.SH，包含后来调出和退市对象 |
| 个股量价与复权 | `daily`、`adj_factor`、`daily_basic` |
| 交易约束与股票信息 | `stk_limit`、`suspend_d`、`namechange`、`stock_basic`；含上市、退市和历史名称 |
| 财务与公告 | `fina_indicator`、`forecast`、`express`；保留 `ann_date`、`end_date` |
| 行业成分 | `index_member_all`；保留纳入与剔除日期 |
| 资金面 | `top_list`、`top_inst`、`margin_detail`、`hk_hold`、`moneyflow_hsgt` |
| ETF行情与复权 | `fund_daily`、`fund_adj`：510300.SH、510500.SH、518880.SH、511010.SH |
| 交易日历 | `trade_cal`，覆盖所需回测区间 |

- Token仅从环境变量 `TUSHARE_TOKEN` 读取，不写入文件、日志、报告或Git。
- 下载采用单进程限流，按接口权限与频率限制留出余量；权限或频率报错时保存进度并停止，不连续轰炸接口。
- 每个数据文件记录来源接口、日期范围、行数和SHA256，清单保存为 `data/MANIFEST.json`。
- 已有数据可按清单核验后复用，不强制重复下载。
- 数据目录只增不删，更新数据写新文件并校验，不静默覆盖已用于研究的数据。
- 准备完成后生成 `reports/data_check.md`，检查日期边界、行情缺口、复权连续性、公告滞后、行业与资金面覆盖；开封前不统计封存内容。
- 接口不可用、权限不足或字段不全时记录缺口，不伪造数据或无声替换来源。

## 8. 随机对照与比较

### 8.1 对照组设置

- 主随机对照使用种子43，组名 `monkey_43`，配置前缀 `m43_`。
- 另外设置20组随机对照，种子1～20，组名 `monkey_1`～`monkey_20`。
- 主随机组与每个随机组的基础配置数量分别等于A组基础配置数量。
- 随机配置生成不根据回测结果迭代，不进行生成阶段的收益择优；生成后走与AI相同的八层筛选和入围流程。
- 对照组使用与AI相同的可用指标、参数档位、股票池、成本及撮合规则，包含自身全量邻域检验和本组N。

### 8.2 比较口径

按以下顺序完整报告：

1. 每层累计存活率：A、B、主随机组并列，20组对照报告中位数、最大值和分位数。
2. 最终达标数量：报告A、B在20组对照中的位置。若各组均为0，不计算无意义的百分位排名，改看L2～L4存活率。
3. 搜索期基础配置的年化超额分布：报告有效样本数、中位数、q25及q75，另列失败数量。
4. 原锁定入围名单、等级、入围分、封存表现，以及两组组合的封存期曲线。

跨组汇总时，明确区分合并全部配置的分布、每组分位数的汇总、每组中位数的分布；图表注释与实际计算对象一致。说明AI与随机对照的预算和生成方式差异，不仅凭搜索期差异作因果归因。

### 8.3 B组提案

- B组在读取项目文件、零件库或运行命令之前，先用自然语言提出策略假设。
- 提案保存为 `notes/search_agent_b_proposal.md`，提交后再查看零件库并落实配置。
- 无法实现的部分记录所缺数据或零件，不将近似替代描述为原假设的精确实现。
- 可申请新增零件，新增后必须审核，并对A组和随机组同时开放。

## 9. 八步执行与交付

| 步骤 | 任务 | 主要产物 |
|---|---|---|
| 1 | 数据准备与核验 | 数据文件、`data/MANIFEST.json`、`reports/data_check.md` |
| 2 | 日期口径、性能优化与回归 | 审计记录、性能报告、回归与边界测试日志 |
| 3 | 零件库与评估指标审核 | 零件说明、指标实现、独立审核记录 |
| 4 | A/B六轮搜索与主随机配置 | 策略配置、台账、研究笔记、`reports/search_summary.md` |
| 5 | 全量L5～L8与入围 | `reports/funnel_summary.md`、`reports/shortlist.md`及逐项结果 |
| 6 | 20组随机对照 | `reports/monkey_independence.md`、`reports/compare.md` |
| 7 | 锁定名单、开封与组合评估 | `reports/sealed_result.md`、六条候选及两组组合、两项基准的结果 |
| 8 | 报告与信号规格 | `reports/试验台账.xlsx`、`reports/研究报告.pptx`、`reports/signals_spec.md` |

每步记录执行范围、开始结束时间、输入输出、错误及处理结果；阶段完成后提交保存。原始供应商数据、凭据和不宜公开的授权材料不纳入公开交付。

## 10. 执行范围与验收

- L5对全部L1～L4幸存基础配置执行，随机对照为20组，不使用缩减样本代替完整研究结果。
- 正式判定前核对每个原定任务的最新状态及有效产物，未完成部分单列，不以任务提交数代替成功完成数。
- 报错恢复沿用原配置、原组和原区间，只重试尚未成功任务，不重新生成更容易通过的参数。
- 性能与资源安排根据机器实际可用内存确定；降低并发不改变研究范围、计算精度和筛选阈值。
- 保存配置、代码、数据清单与结果的对应关系，报告数字可以追溯到原始日收益及汇总文件。
- 累计收益、年化收益、相对基准年化差、超额净值与绝对回撤分别标注，不混用。

## 11. 随机对照独立性

- 随机配置生成时，与台账任何组的已有配置进行规范化去重，重复则重新采样。
- 规范化比较忽略名称等元数据，保留策略结构、因子、权重、参数、持仓与执行条件。
- 不同随机种子之间也执行同样去重，并记录生成数量、重复数量及最终配置集合。
- 配置去重不代表收益独立；策略之间的日超额相关性仍单独报告。

## 12. 并行与性能优化

- 允许多进程回测、共享面板、预计算和缓存复用。
- 成功结果仅在配置、区间、代码与数据口径一致且产物有效时复用；报错记录不视为可复用的成功结果。
- 优化前后抽取不少于50个配置，覆盖规则型、打分型及不同组，全部指标逐位一致。
- 优化后执行未来数据截断测试、封存边界测试和引擎自检，由独立审核角色记录结果。
- 不得通过放宽数值容差、截断历史、抽样日期或降低精度换取加速。
- 同时控制进程数与数值库线程数，避免资源竞争；保存运行参数与实测吞吐。

## 13. 风格体检

- 行业集中度按调仓日持仓权重计算，每个调仓日分别计算行业权重，再汇总平均值。
- 报告行业HHI、最大单一行业权重及主要行业分布。
- 按买入金额汇总成交明细的申万一级行业分布，和持仓口径交叉核对。
- 两种口径相差超过15个百分点时，先查明原因，未核清前不输出结论性数字。
- 行业缺失、历史归属近似、规模或其他显著风格暴露在报告中说明。

## 14. 必报评估指标

以下指标对进入L5的基础策略计算，写入台账和报告，只报告、不新增筛选门槛。

### 14.1 IC、ICIR与分层回测

仅适用于打分型策略：

- 每个调仓日计算策略分数与下一调仓周期收益的截面Spearman秩相关，报告IC均值、标准差、IC为正比例。
- `ICIR = IC均值 ÷ IC标准差 × √年化调仓期数`，周度、月度使用对应期数并注明。
- 按分数分10层，等权持有至下一次调仓，报告各层年化收益、第10层减第1层的年化差及层序与收益的秩相关。
- 分层为信号诊断，不改变仅做多的实际交易约束。
- 单调性较差但IR较高时，单独标记并检查极端个股或集中暴露，不能只凭这一现象断言收益来源。

### 14.2 换手与容量

- 年化换手率：全年买入金额除以平均持仓市值；不足整年的区间注明年化方法。
- 容量粗估：以单日买入不超过该股当日成交额1%为假设，按调仓日配置估计可承载资金，报告中位数和5%分位。
- 容量为模型估计，不包含完整冲击成本，不作为实际可投入资金的保证。

### 14.3 信号衰减

- 对同一信号分别持有1、5、20、60个交易日，计算对应年化超额并绘制衰减曲线。
- 标明取样、持有与成本口径，用于观察信号有效期，不根据封存结果反向选择窗口。

### 14.4 计算边界

- 指标与回测使用同一套时点一致数据，接受未来数据截断测试。
- 搜索期指标只用搜索期数据；验证期同名指标在验证阶段计算，封存期同名指标仅在开封后计算。
- 数据不足或指标不适用时标记原因，不用0代替缺失，也不据此伪造通过结论。
